# 🏛️ Nagpur Connect — Citizen Mobile App (Kotlin / Jetpack Compose) Porting Guide

> **Purpose:** This document provides the exact scope, file context, API contracts, and implementation workflow required to build the **Citizen-Only** Android app in Kotlin without touching or rebuilding the existing web backend, admin consoles, or database.

---

## 1. Context Isolation: Targeted Files (Citizen Only)

To build the Kotlin Citizen app, **you do not need the entire codebase**. The following tables define exactly which files provide citizen business logic, UI state, and API contracts.

### A. Essential Citizen Logic & State Files
| File Path in Web Repo | Relevance to Citizen Kotlin App |
| :--- | :--- |
| `src/app/(citizen)/dashboard/page.tsx` | **The Core Citizen State Machine**: `home` ➔ `composing` ➔ `preview` ➔ `analyzing` ➔ `mismatch` ➔ `analysis` ➔ `dept_questions` ➔ `finalizing` ➔ `final_review` ➔ `submitting` ➔ `success`. |
| `src/modules/incidents/incident-draft.ts` | The `IncidentDraft` data model (text, photos, coordinates, category hint, source: voice/text). |
| `src/modules/incidents/use-incident-draft.ts` | React Hook managing draft state (corresponds to Kotlin `ReportViewModel` state). |
| `src/modules/incidents/category-taxonomy.ts` | 8 official civic categories, subcategories, keywords, icons, emergency flags. |
| `src/modules/incidents/domain/types.ts` | Incident status enum, Severity enum (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`), Citizen tracking labels. |
| `src/modules/speech/use-speech.ts` & `types.ts` | Voice recording state (`idle`, `recording`, `transcribing`, `error`) and transcript merging logic. |
| `src/lib/guest-id.ts` | Client anonymous identity mechanism (`x-guest-id` header & UUID persistence). |

### B. Citizen UI Components to Replicate in Jetpack Compose
| React Component (`src/components/citizen/`) | Jetpack Compose Equivalent | Purpose |
| :--- | :--- | :--- |
| `category-grid.tsx` | `CategoryGrid.kt` (`LazyVerticalGrid`) | Grid of 8 civic categories with icons for quick selection. |
| `draft-preview.tsx` | `DraftPreviewCard.kt` | Card showing drafted text, attached photo thumbnails, GPS pill, and "Analyze" CTA. |
| `photo-uploader.tsx` | `PhotoPickerSection.kt` | Camera / Gallery image picker with thumbnail preview & remove button. |
| `report-analysis.tsx` | `AnalysisResultSheet.kt` | AI assessment display (Detected Department, Severity badge, Summary). |
| `dept-mismatch.tsx` | `DeptMismatchDialog.kt` | Alert shown when citizen picks "Roads" but text describes a "Water Pipe Burst". |
| `dept-questions.tsx` | `DeptQuestionsSection.kt` | Dynamic interactive chips/questions (max 4) generated by AI to refine the report. |
| `tracking-timeline.tsx` | `TrackingTimelineView.kt` | Visual 4-stage stepper: Submitted ➔ Received ➔ Dispatched ➔ Resolved. |

| `src/app/(public)/emergency/page.tsx` | `EmergencyHubScreen.kt` | Emergency quick-dial contacts (112 Police, 101 Fire, 108 Ambulance, 1078 Disaster). |

### C. Backend API Endpoints Consumed by Citizen App
| HTTP Method & Endpoint | File Path in Web Repo | Request Payload / Function |
| :--- | :--- | :--- |
| `POST /api/citizen/register-guest` | `src/app/api/citizen/register-guest/route.ts` | Registers or validates the anonymous citizen UUID. |
| `POST /api/incidents/analyze` | `src/app/api/incidents/analyze/route.ts` | `{ text, locationContext?, selectedDepartment? }` ➔ Returns AI triage, severity, suggested category, department questions. |
| `POST /api/incidents/finalize` | `src/app/api/incidents/finalize/route.ts` | `{ originalText, analysis, answers, locationText }` ➔ Returns consolidated `finalReport`. |
| `POST /api/incidents/create` | `src/app/api/incidents/create/route.ts` | Persists incident into DB with attachments, location, AI assessment, and returns `{ incident: { publicReference } }`. |
| `GET /api/incidents/mine` | `src/app/api/incidents/mine/route.ts` | Header `x-guest-id` ➔ Returns `{ incidents: [...] }` list of citizen's past reports. |
| `GET /api/incidents/{reference}` | `src/app/api/incidents/[reference]/route.ts` | URL param `reference` (e.g. `NAG-2026-000042`) ➔ Returns full live tracking timeline & crew notes. |
| `POST /api/speech/transcribe` | `src/app/api/speech/transcribe/route.ts` | Multipart audio file (Opus/WAV) ➔ Returns `{ transcript: string }`. |

### D. Files to EXCLUDE (Do Not Touch or Port)
- ❌ All Admin routes: `src/app/(admin)/*`
- ❌ All Department consoles: `src/app/(department)/*`
- ❌ All Worker consoles: `src/app/(worker)/*`
- ❌ Database migrations & connection pools: `src/lib/db.ts`, `src/lib/db-migrate.ts`, `src/db/*`
- ❌ Server-side LLM orchestrators: `src/modules/ai/groq-provider.ts` (the Kotlin app calls the API route, not Groq directly)

## 2. Citizen API Contracts (Kotlin Data Models)

### Authentication Header
Every citizen API request should send the stable device ID in the HTTP headers:
```http
x-guest-id: 3fa85f64-5717-4562-b3fc-2c963f66afa6
Content-Type: application/json
```

### 1. Analyze Incident
**Endpoint:** `POST /api/incidents/analyze`
```json
// Request Body
{
  "text": "Deep pothole near Sitabuldi metro station causing severe traffic jam and two-wheeler skids",
  "locationContext": "Sitabuldi, Nagpur",
  "selectedDepartment": "pwd"
}

// Response Body (200 OK)
{
  "success": true,
  "analysis": {
    "mainCategory": "roads_traffic",
    "subcategory": "pothole",
    "title": "Severe Pothole Hazard at Sitabuldi",
    "citizenSummary": "Pothole near Sitabuldi metro causing traffic disturbance and accident risk.",
    "severity": {
      "level": "HIGH",
      "score": 78
    },
    "departments": [
      { "code": "pwd", "name": "Public Works Department", "isPrimary": true }
    ],
    "mismatch": false,
    "suggestedCategory": null,
    "deptQuestions": [
      {
        "id": "q1",
        "question": "Is the pothole deeper than 6 inches or affecting major transit?",
        "type": "single_choice",
        "options": ["Yes, very deep", "Moderate depth", "Minor surface wear"],
        "required": true
      }
    ]
  }
}
```

### 2. Create Incident
**Endpoint:** `POST /api/incidents/create`
```json
// Request Body
{
  "originalText": "Deep pothole near Sitabuldi metro station...",
  "analysis": { /* The analysis object received from analyze */ },
  "locationText": "Sitabuldi Metro Station, Ward 12, Nagpur",
  "latitude": 21.1458,
  "longitude": 79.0882,
  "departmentAnswers": {
    "q1": "Yes, very deep"
  },
  "selectedDepartment": "pwd",
  "attachments": [
    {
      "fileName": "pothole.jpg",
      "mimeType": "image/jpeg",
      "fileSize": 450200,
      "storageUrl": "data:image/jpeg;base64,...",
      "purpose": "evidence"
    }
  ]
}

// Response Body (200 OK)
{
  "success": true,
  "incident": {
    "publicReference": "NAG-2026-000108",
    "title": "Severe Pothole Hazard at Sitabuldi",
    "severity": "HIGH",
    "priorityScore": 78,
    "status": "CONFIRMED",
    "createdAt": "2026-10-02T22:30:00.000Z"
  }
}
```

## 4. Step-by-Step Implementation Workflow

### Step 1: Project Setup & Networking Layer (Day 1)
1. Create a new Android Studio project with **Jetpack Compose Empty Activity**.
2. Add dependencies:
   - `Retrofit2` + `Kotlinx.serialization`
   - `Hilt` for dependency injection
   - `Coil` for image loading
   - `Play Services Location` for GPS
3. Create `CitizenIdentityManager.kt` to generate a UUID on first launch and store it in `SharedPreferences`.
4. Implement `AuthInterceptor` to inject `x-guest-id: <uuid>` into every Retrofit request.
5. Point base URL to your deployed web backend (e.g. `https://nagpur-connect.vercel.app/`).

### Step 2: Emergency Hub & Citizen Home (Day 2)
1. Replicate `src/app/(public)/emergency/page.tsx`:
   - 4 Emergency contact cards (Police 112, Fire 101, Ambulance 108, Disaster 1078).
   - Use Android native `Intent(Intent.ACTION_DIAL, Uri.parse("tel:$number"))`.
2. Build `CitizenHomeScreen.kt`:
   - Header with citizen badge.
   - 3 big CTA cards: "Report an Issue", "Track Grievance", "Emergency SOS".
   - Category Horizontal/Grid selector (from `category-taxonomy.ts`).

### Step 3: Core Incident Reporting State Machine (Days 3–4)
1. Port `useIncidentDraft.ts` into `ReportViewModel.kt` with a sealed class `ReportUiState`:
   ```kotlin
   sealed interface ReportUiState {
       object Composing : ReportUiState
       object Analyzing : ReportUiState
       data class Mismatch(val suggestedDept: String) : ReportUiState
       data class AnalysisReady(val result: AnalysisResult) : ReportUiState
       data class DeptQuestions(val questions: List<DeptQuestion>) : ReportUiState
       object Submitting : ReportUiState
       data class Success(val referenceId: String) : ReportUiState
   }
   ```
2. Integrate native hardware:
   - **Camera:** Simple `ActivityResultContracts.TakePicture()` or `PickVisualMedia()`.
   - **GPS:** Call `fusedLocationClient.lastLocation` to populate latitude & longitude.
   - **Speech:** Use Android's `SpeechRecognizer` with `Locale("en", "IN")` or `Locale("mr", "IN")`.
3. Connect `/api/incidents/analyze` and `/api/incidents/create`.

### Step 4: Grievance Tracking & "My Reports" (Day 5)
1. Build `MyReportsScreen.kt` consuming `GET /api/incidents/mine`.
2. Build `TrackIncidentScreen.kt` consuming `GET /api/incidents/{reference}`.
3. Draw the 4-step tracking timeline:
   - Step 1: `Submitted` (Green check)
   - Step 2: `Routed` to department
   - Step 3: `In Progress` / Field crew dispatched
   - Step 4: `Resolved` with resolution details

### Step 5: Offline Cache & Background Sync (Polish)
1. Setup a Room database for `OfflineDraftEntity`.
2. If the user presses "Submit Report" without internet connectivity, save the draft locally and schedule a `WorkManager` one-time upload worker that fires as soon as network returns.
